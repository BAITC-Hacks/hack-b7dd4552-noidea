# NoIdea · Данные ветропарка

Первый этап HackAlem AI: измерения двух ветротурбин и архивные прогнозы погоды.
Веб-интерфейс показывает мощность, ветер, температуру, полноту данных и
происхождение погодных выпусков. OpenAI-агент управляет инструментами проверки
и прогноза. Подключён HistGradientBoosting по прошлой телеметрии: проверенный
артефакт выбирается для конкретной турбины, CSV, временных настроек и даты.
Если подходящего артефакта нет, используется persistence с явной причиной.
Погодная ML-модель пока не обучена: нет verified-архива выпусков. Просмотр и импорт не требуют ключа;
явный запуск агента использует OPENAI_API_KEY и расходует кредиты.

## Быстрый запуск через Docker

```bash
docker compose up --build -d
```

Открыть **http://localhost:8028**, API: **http://localhost:8028/docs**.

Интерфейс разделён на страницы:

- `/turbines` — список турбин, импорт и просмотр измерений, удаление и восстановление.
- `/turbines/new` — отдельная страница создания турбины.
- `/forecast` — выбор одной или нескольких турбин, периода и запуск прогноза.
- `/weather` — архив отдельных погодных выпусков.
- `/sources` — Open-Meteo по умолчанию и добавление других источников.
Порт можно изменить: `PORT=8030 docker compose up -d`.

При первом запуске список турбин и данные пусты. Добавьте турбину
(название, широта, долгота), затем загрузите её CSV через форму «Измерения».
Никакие примеры автоматически не импортируются. Для загрузки погоды нужен интернет.
Данные и погодный кеш сохраняются в Docker-томе `wind-data`.
Остановка: `docker compose down` (данные в томе сохраняются).

## Локальная разработка

Требуются uv, Python 3.12 (uv может установить его) и Node.js 24+.

```bash
uv sync --frozen
npm --prefix frontend ci
npm --prefix frontend run build
uv run uvicorn wind.app:app --host 127.0.0.1 --port 8027
```

Открыть **http://localhost:8027**. Для разработки React с горячей перезагрузкой
запустить `npm --prefix frontend run dev` во втором терминале; Vite проксирует
`/api` на `127.0.0.1:8027`. Адрес Vite появится в терминале.

## Добавление турбины и импорт через веб

1. Нажать «Добавить турбину»: откроется `/turbines/new`. Указать название, широту и долготу,
   затем нажать «Создать турбину». Откроется список с выбранной новой турбиной.
   «Отмена» возвращает к списку без создания.
2. В карточке турбины выбрать CSV и нажать «Импортировать CSV».
3. Проверить количество строк, полноту часов и графики.
4. При необходимости загрузить архивный выпуск погоды для координат турбины.

CSV: UTF-8, разделитель запятая, максимум 25 МБ. Поддерживаются исходные
русские заголовки организаторов (подсказка есть в форме). Время без смещения,
шаг 10 минут, мощность нормализованная [0,1]. После ошибочного импорта
активный набор не меняется. Успешный повторный импорт заменяет активный набор,
сохраняя прежние исходники. Можно создать любое количество турбин.

Удаление доступно для выбранной турбины по кнопке «Удалить турбину» с отдельным
подтверждением. Это перемещение в корзину: турбина исчезает из рабочих списков,
новые расчёты и импорт для неё блокируются. CSV, погода, история и прогнозы
сохраняются. В разделе «Удалённые турбины» можно восстановить её вместе с данными.
Идентификаторы удалённых турбин не переиспользуются.

## Дополнительный импорт через CLI

Сначала создайте турбины в веб-интерфейсе. CLI ожидает по файлу
`turbine <id>.csv` для каждой зарегистрированной турбины.

CSV организаторов положить в одну папку. Имена должны заканчиваться
на `turbine <id>.csv`, по одному файлу на зарегистрированную турбину.

```bash
uv run python -m wind.ingest --source-dir /home/qialsyz/Загрузки
```

Для Docker выполнить одноразовый импорт, подключив папку CSV только
для чтения (заменить путь на свой):

```bash
docker compose run --rm -v "/home/qialsyz/Загрузки:/input:ro" web /app/.venv/bin/python -m wind.ingest --source-dir /input
```

Обновить страницу после импорта. Локальные данные сохраняются
в `./data/workspace`; другой путь задаётся переменной окружения `DATA_DIR`.
Приложение не читает `.env` автоматически: для локального запуска переменные
нужно экспортировать в оболочке. Compose читает `PORT` из `.env`.

Импорт сохраняет исходный CSV без изменений, SHA-256, нормализованный
10-минутный Parquet и почасовой Parquet. SQLite хранит каталог активных версий.
Повторный импорт не создаёт вторую запись турбины в каталоге.
Версии исходных файлов сохраняются. Полная история не включена в Git.

## Что проверить в интерфейсе

1. Переключить турбину: изменятся статистика, координаты и графики.
2. Выбрать период до 93 дней и нажать «Показать»; переключить мощность,
   ветер и температуру. Наведение на график показывает час и значение.
3. Для полной истории посмотреть май–июль 2024 у первой турбины: длинные
   пропуски остаются разрывами. Таблица ниже показывает крупнейшие разрывы.
4. Скачать почасовой CSV выбранного периода.
5. В погоде выбрать 31.01.2026, 00 UTC и нажать «Загрузить выпуск».
   Появятся 72 часа ECMWF, статистика отсутствующих значений и исходный JSON.
6. Повторить запрос: ответ берётся из кеша. Сохранённый выпуск также
   можно выбрать из списка без обращения к погодному провайдеру.

## Правила качества и времени

- Исходный шаг — 10 минут. Некорректные даты, отметки вне сетки,
  дубликаты, отрицательный ветер и мощность вне [0,1] отклоняют импорт.
- Нечисловые/пустые значения отмечаются как отсутствующие.
- Почасовое среднее доступно только при шести валидных значениях каждого
  показателя. Для неполного часа все средние — `null`, без интерполяции.
- `sample_count` — число строк, `valid_count` — минимум числа валидных
  значений среди трёх показателей, `completeness = valid_count / 6`.
  `quality`: `complete`, `partial`, `missing`.
- Часовой пояс CSV **не подтверждён**. Время сохранено как в источнике.
  Предположение — `Asia/Almaty`; регион перешёл с UTC+6 на UTC+5 в марте 2024.
  [Официальное сообщение](https://www.gov.kz/memleket/entities/mti/press/news/details/688998?lang=ru).
  Неизвестно также, timestamp обозначает начало или конец 10-минутного интервала.
- Погода хранится в UTC, её графики отделены от измерений. Автоматического
  совмещения времён и пригодного для обучения объединённого датасета пока нет.
- `run` — инициализация модели, `retrieved_at` — текущая загрузка архива.
  Историческое время публикации неизвестно: `available_at=null`,
  `historical_eligibility=unverified`. Выпуск нельзя считать допустимым
  для исторического расчёта без отдельной проверки доступности.
- Запрашивается явная модель `ecmwf_ifs`, температура 2 м, ветер 10/100 м и
  направление 100 м. Единицы — °C, м/с, градусы. Ветер 100 м не объявляется
  ветром на высоте ступицы: высота турбин неизвестна.
- Координаты ячейки погоды могут отличаться от координат турбин; близкие
  турбины могут попадать в одну ячейку. Оба вида координат сохранены в метаданных.
- Нормализованная мощность — доля номинала, **не кВт и не кВт·ч**.

В ранее исследованных файлах организаторов: 142 360 строк турбины 1 и 149 499 строк турбины 2,
период 11.03.2023–31.01.2026. Фактических измерений тестового февраля 2026 нет.

## API и интеграция ML

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/health` | Проверка сервера |
| GET | `/api/turbines` | Каталог турбин и качество; has_data показывает наличие CSV |
| POST | `/api/turbines` | Создание: name, latitude, longitude |
| DELETE | `/api/turbines/{id}` | Перемещение в корзину без стирания данных |
| GET | `/api/turbines/deleted` | Корзина турбин |
| POST | `/api/turbines/{id}/restore` | Восстановление турбины с данными |
| POST | `/api/turbines/{id}/import` | multipart/form-data, поле file: CSV |
| GET | `/api/turbines/1/series?start=2026-01-25&end=2026-01-31` | Почасовые точки, даты включительно |
| GET | `/api/turbines/1/export?start=2026-01-25&end=2026-01-31` | Почасовой CSV |
| POST | `/api/weather` | Загрузка/кеширование выпуска |
| GET | `/api/weather?turbine_id=1` | Сохранённые выпуски |
| GET | `/api/weather/{id}` | Метаданные и точки |
| GET | `/api/weather/{id}/raw` | Исходный ответ провайдера |

Пример тела `POST /api/weather`:

```json
{"turbine_id": 1, "run": "2026-01-31T00:00:00+00:00"}
```

Почасовой контракт: `time`, `wind_speed`, `power`, `temperature`,
`sample_count`, `valid_count`, `completeness`, `quality`.
В каталоге — `hourly_path`, `sha256`, `timezone="unconfirmed"`.
ML-модуль может читать Parquet по относительному пути из каталога.
Погода: `time` в UTC, `temperature_2m`, `wind_speed_10m`,
`wind_speed_100m`, `wind_direction_100m`; рядом метаданные выпуска и запроса.

## Агент и проверка реакции

Сохраните `OPENAI_API_KEY` в `.env` (вне Git), при необходимости задайте
`OPENAI_MODEL` (по умолчанию gpt-4.1-mini). Для локального агента .env читается
автоматически; DATA_DIR лучше задавать явно в окружении при запуске сервера.
После изменения окружения Docker выполните `docker compose up -d`.
На странице `/forecast` выберите турбины и начало/конец прогноза в UTC
(обе границы включены, шаг — час, всего 24–48 часов). Например,
01.02.2026 00:00 — 02.02.2026 23:00 — это 48 почасовых точек.
Момент расчёта — за час до начала выбранного диапазона; он не может быть в будущем.
Для каждой турбины укажите часовой пояс CSV и смысл временных отметок.
Измерения должны быть доступны к моменту расчёта и не старше двух часов.

Кнопка «Проверить данные» вызывает `/api/agent/preflight`: проверяет локальные
измерения без LLM, загрузки погоды и расхода API-кредитов. Перед каждым запуском
такая проверка повторяется. Турбины обрабатываются последовательно; ошибка одной
не мешает проверить остальные. Результаты и история отображаются по каждой турбине.

Агент ограничен 10 шагами. Он проверяет данные, пытается получить погоду,
строит ML-прогноз или резервный baseline, проверяет и сохраняет результат. Неподтверждённое время и
устаревшие измерения блокируют прогноз. Это не обученный погодный прогноз.
Автоматического платного запуска после импорта нет.

```bash
uv run python -m wind.simulate
```

Команда расходует API-кредиты и проверяет шесть событий на изолированных
синтетических данных с настоящими решениями LLM. Пользовательский каталог не меняется.
Результаты и ограничения: [docs/agent.md](docs/agent.md).

## Обучение и защита ML от утечек

Полный аудит: [docs/ml/data-audit.md](docs/ml/data-audit.md).
Модель использует только уже доступные измерения мощности, ветра и температуры,
их лаги/скользящие статистики и календарь. Будущие измерения и фактическая погода
не подаются в признаки. Временная семантика применяется к исходным 10-минутным
отметкам **до** агрегации.

Обучение выполняется явно через CLI после импорта полных CSV. Оно не вызывает
OpenAI. Для текущих исходников рабочая гипотеза — постоянное UTC+6 (`Etc/GMT-6`);
семантику выбирайте явно, она ещё не подтверждена организатором:

```bash
docker compose exec -T web /app/.venv/bin/python -m wind.ml train --all \
  --measurement-timezone Etc/GMT-6 --timestamp-semantics interval_start \
  --train-end 2025-10-01T00:00:00Z \
  --validation-end 2026-01-01T00:00:00Z --test-end 2026-02-01T00:00:00Z
```

Для второй гипотезы запустить ту же команду с `--timestamp-semantics interval_end`.
Для одной турбины заменить `--all` на `--turbine-id ID`. Для нативного запуска:
`uv run python -m wind.ml train ...` с тем же `DATA_DIR`, что у сервера.
Семидневные примеры не подходят для этих фиксированных периодов; нужно не менее
30 суток полных целей обучения и 7 суток целей в каждом проверочном периоде.

Обучение получает цели только до 01.10.2025, валидация — октябрь–декабрь,
контроль — январь. Пересекающие границы горизонты исключаются. Нет случайного
разбиения и внутреннего random early stopping; модель не дообучается на
валидации/контроле. Решение использовать ML принимается по MAE валидации,
**до** вычисления январских метрик. Январь уже изучался ранее, поэтому он не
называется независимым нетронутым тестом; февральских ответов пока нет.

Артефакты сохраняются в `DATA_DIR/models/` (в Docker-томе): веса, manifest,
отчёт с метриками и точные отпечатки обучающих строк. В Git их нет. На странице
«Прогноз» видны доступность модели и периоды проверки; API — `GET /api/ml/models`.
Новый CSV требует переобучения; чужой ID, несовпадающие часы, повреждённые веса,
версия sklearn или расчёт раньше окончания валидации приводят к явному fallback.
Модель не используется для ретропрогнозов внутри своего обучения/валидации.

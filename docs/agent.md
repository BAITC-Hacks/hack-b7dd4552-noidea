# Агент: инструменты и проверка событий

OpenAI Responses API с function calling, модель по умолчанию `gpt-4.1-mini`.
Ключ читается из `.env` или окружения. Docker получает OPENAI_API_KEY и
OPENAI_MODEL как переменные; .env не копируется в образ.

| Инструмент | Назначение |
|---|---|
| inspect_data | Наличие данных, профиль качества всей загрузки, готовность времени |
| prepare_features | Только полные часы, уже доступные на issue_at; исключает будущее; блокирует возраст телеметрии >2 ч |
| fetch_weather | Архивный выпуск, максимум две попытки; доступность в прошлом остаётся unverified |
| predict_power | 24–48 точек persistence baseline из последней доступной мощности |
| check_forecast | Проверка времени, длины, диапазона и конечности чисел |
| save_forecast | Запись только проверенного результата, с повторной валидацией |

Турбина и момент расчёта фиксируются сервером. Произвольные shell, SQL, URL
и файловые операции модели недоступны. До 10 запросов OpenAI, до 700 выходных
токенов на запрос; автоматических повторов запросов к OpenAI нет. В веб-API
одновременно выполняется один запуск на процесс.

## Запуск

Веб: блок «Запуск агента». Задать момент в UTC, часовой пояс CSV и смысл
исходной 10-минутной отметки. Если эти сведения неизвестны, оставить
«Не подтверждено»: расчёт должен остановиться. Запуск расходует API-кредиты.

```bash
uv run python -m wind.agent --turbine-id 1 --issue-at 2026-02-01T00:00:00Z --measurement-timezone Asia/Almaty --timestamp-semantics interval_start
```

Временные параметры в примере не подтверждают время файлов организаторов.
Измерения считаются доступными в конце интервала, без задержки доставки.
Неоднозначные местные времена отклоняются. Признаки строятся из исходного
10-минутного Parquet с учётом interval_start/interval_end.

API: `GET /api/agent/status`, `POST /api/agent/runs`,
`GET /api/agent/runs?turbine_id=1`, `GET /api/forecasts/{id}`.
Журналы: `DATA_DIR/agent-runs`, прогнозы: `DATA_DIR/forecasts`.
Перезагрузка страницы показывает последний отчёт для выбранной турбины.

## Проверенный эксперимент 23.09.2026

Шесть сценариев с реальной OpenAI LLM и синтетическими измерениями. В обычном
сценарии получен реальный архив Open-Meteo; в остальных погодные ответы/отказы
имитируются и явно помечаются. Каждый сценарий работает во временном каталоге,
пользовательские данные не меняются.

| Сценарий | Реакция | Результат |
|---|---|---|
| healthy | Проверка → признаки → погода → baseline → контроль → сохранение | 48 значений 0,40 |
| missing_hours | Пропуски сохранены, использован свежий полный час | 48 значений 0,40 |
| weather_outage | Две попытки погоды, затем baseline без погоды | Прогноз сохранён |
| stale_telemetry | Остановка: возраст 6 ч при максимуме 2 ч | Прогноза нет |
| time_unconfirmed | Остановка после проверки времени | Прогноза нет |
| data_updated | Пересчёт по обновлённым измерениям | 48 значений 0,65 |

Во все CSV добавлены будущие значения 0,99; они не попали в прогноз.
6/6 сценариев прошли проверку действий и чисел. Расход: 25 390 входных и
677 выходных токенов. Это проверка оркестрации, не оценка точности ВЭС.

В одном свободном пояснении LLM ошибочно назвала погоду неполной. Поэтому
`summary` теперь формируется из проверенных результатов инструментов.
Исходное `llm_summary` хранится отдельно как непроверенное пояснение.
Решения о вызовах инструментов по-прежнему принимает модель.

Повторить живую проверку (расходует кредиты):

```bash
uv run python -m wind.simulate
```

Отчёты: `data/agent-validation/<id>/` вне Git. События manual/data_updated/
weather_updated подаются явно через форму или API. Постоянный планировщик и
автозапуск после импорта не включены: импорт сам по себе не тратит кредиты.

## Ограничения

Используется только persistence. Обученный бустинг из отдельной ML-ветки ещё
не интегрирован. Погода не используется в признаках. Выпуск запрашивается
с запасом 12 часов; это эвристика, а не доказательство исторической доступности.
Без фактических данных февраля качество финального теста не оценить.
Сервер предназначен для localhost: авторизация и изоляция пользователей
пока не реализованы. Данные измерений в полном объёме в LLM не отправляются:
только результаты инструментов и сводки. Профиль inspect_data относится
ко всей загрузке, поэтому сам по себе не является временным срезом для бэктеста.

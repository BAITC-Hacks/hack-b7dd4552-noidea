# Проверка времени измерений, 23 сентября 2026

Вывод: постоянное UTC+6 — наиболее обоснованная рабочая гипотеза для обоих
исходных файлов на всём периоде 11.03.2023–31.01.2026. Это эмпирический вывод,
не подтверждённая настройка SCADA. Часовой пояс приложения и исходные данные
автоматически не изменены. Точность до минуты и начало/конец интервала не установлены.

## Данные и метод

- Полные локальные нормализованные исходники `data/1-*-10min.parquet` и
  `data/2-*-10min.parquet`, 142360 и 149499 строк соответственно.
- Открытые архивы ERA5 и ECMWF IFS через
  [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api).
  Запрошены 10.03.2023–01.02.2026, GMT, ветер 10/100 м в м/с и температура 2 м.
- Запрос в точке первой турбины 43.645150, 78.535604; один общий внешний ряд
  для двух близко расположенных турбин. Выбранные ячейки: ERA5 43.75, 78.5;
  IFS 43.620384, 78.47891. Это модельные сеточные данные, не метеостанция на площадке.
- Проверены все целочасовые смещения UTC−12…UTC+14 и `Asia/Almaty` из zoneinfo.
  Положительное смещение означает `UTC = время CSV − смещение`.
- Основное сравнение: исходные измерения на отметках `HH:00`, без заполнения
  пропусков. 23722 пары для первой турбины и 24912 для второй при фиксированных
  смещениях. Для `Asia/Almaty` исключён неоднозначный час перехода.
- Pearson r рассчитан для ветра, мощности против внешнего ветра и температуры;
  отдельно весь период, до/после 01.03.2024 и каждый месяц (минимум 100 пар).
  Проверены также трёхчасовые изменения, чтобы уменьшить влияние медленных трендов.
- Проверка чувствительности: среднее шести измерений полного часа против
  интерполированной погоды в среднем физическом времени интервалов, для обеих
  гипотез начала/конца 10-минутного интервала. Среди +5/+6/+7 во всех восьми
  комбинациях модель × турбина × семантика победил +6.

## Результаты

Корреляция измеренного ветра с внешним ветром на 100 м за весь период
(больше — лучше; это не доля правильных предсказаний):

| Гипотеза | IFS, турбина 1 | IFS, турбина 2 | ERA5, турбина 1 | ERA5, турбина 2 |
|---|---:|---:|---:|---:|
| UTC | 0.339 | 0.332 | 0.376 | 0.371 |
| UTC+5 постоянно | 0.745 | 0.744 | 0.718 | 0.714 |
| **UTC+6 постоянно** | **0.771** | **0.769** | **0.741** | **0.737** |
| UTC+7 постоянно | 0.742 | 0.740 | 0.726 | 0.722 |
| UTC+8 постоянно | 0.684 | 0.682 | 0.677 | 0.672 |
| Asia/Almaty, с переходом | 0.757 | 0.753 | 0.728 | 0.724 |

После 01.03.2024 IFS: +6 даёт 0.7795/0.7749, +5 — 0.7570/0.7517.
До перехода также выигрывает +6 среди фиксированных смещений.
В месячном сравнении всех фиксированных смещений +6 лучший у IFS в 31/34
и 31/35 пригодных месяцев; у ERA5 — в 27/34 и 28/35.
Для мощности против ветра IFS +6 также лучший за весь период: r=0.7316/0.7395.

Существенное противоречие: температура лучше совпадает при +7, а не +6.
Для IFS за весь период r(+7)=0.9829/0.9829, r(+6)=0.9813/0.9812.
Разность за три часа не устраняет полностью это расхождение. Возможны
особенности датчика, локального суточного хода или модели; причина не установлена.
Высокая корреляция температур сама по себе не доказательство из-за сезонности.

## Интерпретация и ограничения

[Официальный перевод часов](https://www.gov.kz/memleket/entities/mti/press/news/details/688998?lang=ru)
на UTC+5 не доказывает изменение часов оборудования. Результаты согласуются
с тем, что SCADA продолжила писать UTC+6 после перехода, но не доказывают это.
Две турбины одной площадки и два продукта ECMWF не являются четырьмя полностью
независимыми подтверждениями. Сеточная погода может иметь систематический
временной сдвиг относительно локального ветра. Не каждый месяц выбирает +6.

Рабочее преобразование для дальнейших экспериментов: `UTC = timestamp − 6h`,
с пометкой `inferred`, не `confirmed`. Использовать постоянное смещение, а не
`Asia/Almaty`. Для окончательного подтверждения запросить настройки SCADA или
событие с известным UTC (например, журнал остановки). Для проверки прогноза
зафиксировать гипотезу до оценки модели на отдельном тестовом периоде.

Загруженный исторический архив нужен для диагностики часов. Его нельзя выдавать
за погодный прогноз, доступный в исторический момент принятия решения.

## Воспроизведение

При наличии указанных локальных parquet:

```bash
uv run python scripts/audit_timezone.py --download
```

Без `--download` расчёт работает офлайн по сохранённым ответам. Результат:
`data/timezone-audit/scores.json` — все смещения, месяцы, чувствительность,
ячейки сетки и SHA-256 ответов. Архивы и результаты остаются в игнорируемой
папке `data/`. API-ключи и платные вызовы OpenAI не используются.

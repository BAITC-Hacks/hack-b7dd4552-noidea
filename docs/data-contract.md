# Контракт первого этапа для ML

Состояние: первый этап работает локально, ещё не отправлен в GitHub.
Доступ через HTTP API или локальные Parquet, без импорта frontend/HTTP-кода в ML.

## Измерения

Каталог: `GET /api/turbines`, поле `items`.
Каждая зарегистрированная турбина имеет `id`, название, координаты и `has_data`.
До импорта CSV полей измерений нет. После импорта появляются `hourly_path`, `sha256`, границы, статистика качества,
`dataset_kind` (`full` либо `demo`) и `timezone="unconfirmed"`.
`hourly_path` считается относительно `DATA_DIR` (по умолчанию `data/workspace/`).

| Поле Parquet | Тип | Значение |
|---|---|---|
| time | datetime без timezone | Начало часового бакета в времени CSV |
| wind_speed | float / null | Средний ветер, м/с; высота измерения неизвестна |
| power | float / null | Средняя нормализованная мощность, [0,1] |
| temperature | float / null | Средняя температура, °C |
| sample_count | int | Число исходных строк в часе |
| valid_count | int | Минимум числа валидных значений по трём метрикам |
| completeness | float | valid_count / 6 |
| quality | string | complete / partial / missing |

Для `quality != complete` все три численные метрики равны null.
Исходные значения не интерполируются. Часовые бакеты включают отсутствующие часы
между первым и последним наблюдением. Вне границ исходного ряда часы не добавляются.
В HTTP JSON null сохраняются; time передаётся ISO-строкой без смещения.

Значения часа H используют наблюдения с отметками [H, H+1h), поэтому их нельзя
считать доступными в начале H. Семантика исходного timestamp (начало/конец
интервала), задержка телеметрии и timezone ещё требуют подтверждения.

## Погода

`GET /api/weather?turbine_id=1` возвращает метаданные сохранённых выпусков;
`GET /api/weather/{id}` дополнительно содержит `points`.

Точки: `time` с +00:00, `temperature_2m` (°C), `wind_speed_10m` и
`wind_speed_100m` (м/с), `wind_direction_100m` (градусы).
Ровно 72 последовательных часа от инициализации выпуска, включая час 0.
Это не обещание 72 будущих часов относительно момента публикации выпуска.
Отдельные null разрешены и подсчитываются; полностью пустая переменная отклоняется.

Метаданные: `id`, `turbine_id`, `run`, `retrieved_at`, `model`, `request_url`,
`request_params`, `raw_path`, `sha256`, `units`, `missing_values`,
`grid_latitude`, `grid_longitude`, `available_at`, `historical_eligibility`.
Сейчас `available_at=null` и `historical_eligibility="unverified"`.
Параметры запроса хранят координаты турбины, grid-поля — координаты модели.

Архив не объединён с измерениями. Нельзя использовать `retrieved_at` как время
исторической доступности или приравнивать `run` к публикации. Нельзя молча
назначить CSV часовой пояс UTC либо постоянное смещение +05:00 на всю историю.

## Локальная проверка

Пользовательская версия с пустым начальным состоянием: `http://127.0.0.1:8027`.
Docker-версия: `http://127.0.0.1:8028`, отдельный том, также без автоматического импорта.
Это локальные адреса, процессы могут быть остановлены; запуск описан в README.
Координаты и единицы доступны в каталоге/API без чтения закрытых настроек.

Для интеграции ML необходимо явно согласовать timezone, время доступности
погодных выпусков, семантику timestamp и момент выдачи прогноза.

Предыдущая полная история сохранена в data/ с прежним каталогом; она не удалена.
Для новой турбины POST /api/turbines; CSV — POST /api/turbines/{id}/import, поле file.

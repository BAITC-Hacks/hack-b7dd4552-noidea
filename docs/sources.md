# Настраиваемые погодные источники

Отдельная страница `/sources` открывается через меню «Источники».
На ней по умолчанию видна карточка встроенного Open-Meteo и кнопка
«Добавить источник». Карточка представляет уже используемый сервис, не создаёт
фиктивный URL запроса и не запускает загрузки автоматически. Пользовательские
подключения из реестра отображаются рядом; их можно редактировать и выключать.
Поддерживаются публичные HTTPS GET-адреса, JSON (массив объектов либо объект
массивов одинаковой длины) и CSV UTF-8. Параметры запроса задаются в URL.
Ключи и пароли в URL не вводить: конфигурация сохраняется и доступна в API.

## Проверка через интерфейс

1. Откройте Open-Meteo для автоматического подбора или нажмите «Добавить источник».
   Для готового URL API раскройте «Настроить API вручную» и укажите адрес и формат.
2. Отметьте адрес как доверенный. Это разрешает загрузку, но не подтверждает
   правильность единиц, времени или пригодность для ML.
3. Вставьте выдержку документации и нажмите «Предложить настройки агентом».
   Один вызов OpenAI, максимум 1500 выходных токенов, без автоматических повторов.
   Модель получает ограниченный образец ответа и выдержку документации.
4. Просмотрите предложение, список неизвестных параметров и результат проверки.
   «Перенести в форму» не сохраняет настройки. Исправьте их при необходимости.
5. Сохраните настройки, выполните «Проверить загрузку», затем «Загрузить и сохранить».
   Ручная настройка полностью доступна без OpenAI.

Укажите путь к массиву JSON (например `hourly` или `data.rows`), имена полей,
часовой пояс IANA, единицы, высоту ветра и смысл отметки времени.
Постоянное UTC+6: `Etc/GMT-6`; `Asia/Almaty` учитывает исторический перевод часов.
Неизвестные параметры блокируют нормализацию, а не заполняются догадкой.
Известное смещение внутри ISO-строки должно совпадать с выбранным поясом.

## Сохранение и ограничения

Каждое редактирование увеличивает revision. Нормализация проверяет все строки,
отклоняет дубли времени, неоднозначное время, пропуски обязательных значений,
NaN/Inf и неверные диапазоны. Ветер преобразуется в м/с, температура в °C,
время — в UTC. Смысл интервала сохраняется в конфигурации; временные отметки
не сдвигаются произвольно к началу/концу часа. Высота ветра не пересчитывается.

Загрузки сохраняются в `DATA_DIR/source-runs/<id>/`: исходные байты и normalized.json
со снимком конфигурации, её версией, SHA-256 и временем получения. При ошибке
нормализации новая загрузка не сохраняется. Предпросмотр не создаёт архив.

Ограничения: ответ до 2 МБ, до 50000 строк, без редиректов, локальных IP,
пагинации, авторизации и произвольного исполняемого кода. DNS-адрес проверяется
и закрепляется на время HTTPS-соединения с проверкой сертификата исходного хоста.
Сервис рассчитан на локальное использование: пользовательской авторизации пока нет.

Предложения LLM проходят Pydantic и пробную нормализацию, но модель может ошибиться
в смысле данных. Результат всегда требует просмотра пользователем; он не меняет
доверие к адресу и не активирует предложенную конфигурацию сам.

Встроенный диагностический адаптер ECMWF Single Runs остаётся отдельным.
Погодная ML-модель подключается через специальный адаптер NOAA GFS/Dynamical,
описанный ниже. Произвольная запись реестра JSON/CSV не становится автоматически
входом этой модели: нужны привязка к турбине, совпадение модели/полей с обучением
и проверяемый контракт выпуска и публикации. Persistence и телеметрическая
ML-модель погодные признаки не используют. У обычных загрузок реестра
`available_at=null`, `historical_eligibility=unverified`: время загрузки сейчас
не доказывает доступность данных в прошлом.

## Исторический выпуск для погодной модели

Месячный февральский прогон использует NOAA GFS 0.25° через архив Dynamical.
Это специальное подключение в `wind.archive`, а не новый пользовательский
парсер, автоматически построенный LLM. Оно выбирает выпуск по `issue_at`
и проверяет весь требуемый горизонт перед прогнозом.

Точки сохраняют `run` и время публикации своего исходного объекта. Общий
`available_at` результата — максимум Last-Modified исходных NOAA GRIB-объектов
для используемых часов. Все эти объекты должны быть
опубликованы не позднее момента расчёта. Только после проверки возвращаются
`historical_eligibility=verified` и `eligible=true`. При временном отказе
допускается одна попытка более раннего выпуска той же модели. Подмена
архивом фактической погоды или другим провайдером не выполняется.

Вместе с точками сохраняются координаты/ячейка, версия и снимок архива,
SHA-256, URLs и метаданные объектов, послужившие свидетельством публикации.
Публикация оригинального NOAA GRIB не означает, что API Dynamical уже существовал
в прошлом. Воспроизводимость учитывает последующее преобразование прогноза,
включая округлённые компоненты ветра. Контракт и ограничения описаны в
`docs/data-contract.md`; при несовместимости с обучением расчёт останавливается.

Пользовательский флаг «доверенный источник» разрешает HTTP-загрузку,
но не устанавливает `historical_eligibility=verified`. Агент не может получить
пригодный для бэктеста источник одной догадкой о задержке публикации.

## API

- GET/POST `/api/sources` — список и создание.
- PUT `/api/sources/{id}` — редактирование, включая trusted/enabled.
- POST `/api/sources/suggest` — предложение настроек по несохранённой конфигурации.
- POST `/api/sources/{id}/preview` — загрузить и проверить, без сохранения.
- POST `/api/sources/{id}/load` — загрузить, проверить и сохранить.
- GET `/api/sources/batches/{id}` — сохранённый нормализованный набор.

Функции адаптации находятся в `src/wind/sources.py`: download, parse, normalize,
suggest, load_source. Новый JSON/CSV в поддерживаемой структуре обычно требует
только конфигурации. Для иной авторизации или формата нужен дополнительный адаптер.

## Проверки реализации

При первоначальном добавлении реестра прошли 42 теста проекта, включая CSV/JSON, смену схемы, неправильные значения,
часовые пояса, версии настроек, отсутствие записи при ошибке, проверку предложения
агента, запрет внутренних IP/редиректов и ограничение размера ответа.
Реальная проверка 23.09.2026: ERA5 за 25.01.2026 через публичный Open-Meteo API;
GPT-4.1 mini предложил hourly/time/wind_speed_100m/temperature_2m, Etc/GMT, м/с,
°C, 100 м и instant. Все 24 строки прошли нормализацию. Использовано 797 входных
и 227 выходных токенов. Пользовательский каталог источников этим тестом не изменялся.


## Подключение по одному адресу сайта

Откройте карточку Open-Meteo или нажмите «Добавить источник», чтобы увидеть
форму «Подобрать данные по сайту». Выберите турбину
с импортированными измерениями, введите `open-meteo.com` или полный адрес страницы
документации, выберите цель и нажмите «Найти и проверить запрос».

Сервер передаёт модели координаты, диапазон дат, число строк и SHA-256 импорта,
но не весь CSV. Агент читает главную страницу и найденные ссылки документации
(до 4 страниц, до 6 обращений к модели, максимум 2000 выходных токенов на обращение).
Каждое обращение получает только извлечённый текст и ссылки; код сайта не выполняется.
Для API используются только HTTPS-адреса выбранного сайта и его поддоменов.
Endpoint должен присутствовать на прочитанной странице. Другой домен, ключи,
POST-запросы, нестандартное кодирование дат требуют отдельной настройки.

Агент предлагает названия параметров, переменные, единицы и соответствие полей.
Координаты и даты подставляет сервер. Некорректные предложения и ошибки HTTP 400
возвращаются агенту для исправления в пределах того же лимита шагов.
Первый запрос проверяет один день. Готовый план показывает адрес API, документацию,
предпросмотр, журнал, количество частей и расход токенов.

«Загрузить весь период» создаёт запись в реестре и последовательно загружает
части до 31 дня. Можно остановить после текущей части или продолжить после сбоя.
План и уже загруженные части сохраняются на сервере; последний план выбранной
турбины восстанавливается по идентификатору из localStorage браузера.
Одна часть сохраняется только после проверки всех строк и полного почасового
покрытия дат. Неудачная часть не считается выполненной. Максимум 48 частей.
При изменении импорта, координат либо настроек источника продолжение блокируется:
необходимо создать новый план. Блокировка операций рассчитана на один процесс
приложения (как в текущем Docker Compose).

Цели:
- История: архив за период CSV с запасом по одному календарному дню с обеих сторон.
- Исторические прогнозы: API исторических прогнозов, без подмены реанализом.
- Текущий прогноз: погода на сегодня и завтра по UTC.

Запас по датам не устанавливает часовой пояс CSV. Высота внешнего ветра берётся
из документации переменной; она не считается высотой ступицы турбины.
В этом универсальном сценарии доступность каждого исторического выпуска на
момент расчёта ещё не доказана: результаты остаются `historical_eligibility=unverified`
и не используются автоматически в ML-бэктесте. Календарный ряд historical forecast сам по себе не хранит
полный контракт issue_at/available_at/lead_time. Для честной оценки нужны отдельные
выпуски прогнозов и проверка времени публикации.

Статический HTML и найденные ссылки поддерживаются. Сайты с JavaScript-only
документацией, перенаправлениями, авторизацией или неподдерживаемой схемой могут
потребовать уточнения; успешное автоматическое подключение любого сайта не обещается.
Здесь нет внешнего поискового индекса: поиск ограничен ссылками выбранного сайта.

API: POST `/api/discovery/plan` (site, turbine_id, purpose);
GET `/api/discovery/plans/{id}`; POST `/api/discovery/plans/{id}/next`.
Планы хранятся в `DATA_DIR/discovery`. Новые источники видны в общем реестре.

Реальная проверка поиска 23.09.2026: ввод только `open-meteo.com`, турбина с
семидневным демонстрационным CSV. Агент открыл историческую документацию, получил
HTTP 400 для `temperature_unit=C`, исправил на `celsius`, затем исправил `rows_path`
на `hourly` после ошибки структуры. Проверены 24 часа; весь период с запасом по
датам загружен успешно — 216 строк. Успешный прогон: 39100 входных и 807 выходных
токенов; предварительные неуспешные прогоны при разработке тоже использовали API.
Результаты сохранены локально в `data/discovery-validation/`; тестовый каталог был
изолирован от пользовательского. После прогона добавлена передача ограниченного
образца ответа в обратную связь при ошибке структуры, чтобы агент не угадывал поля.
